# 单人多设备同步：实验性手动同步

**简体中文 | [English](SYNC.en.md)**

Windows v0.7.0 公开预览版已接入应用设置与本地文件库；2026-10-15 已使用人工导图完成坚果云真实接口测试，
尚未完成两台实际设备的界面级测试。默认不联网，
不会自动上传任何用户导图。无需注册 iThread 账号；使用 WebDAV 时需要用户自己的
存储服务及访问凭据。尚未建立任何服务器或产生云服务订阅。

## 已实现

- `src/sync/engine.ts`：平台无关的同步协议、三方版本比较，以及本地存储适配接口。
- `src/sync/webdav.ts`：WebDAV 目录发现、文档读取和条件写入。通过注入请求函数连接
  不同平台的网络与安全凭据层，核心引擎不保存密码。
- 以共同基准版本比较本地与远端：仅单边修改则上传或下载，双方修改则保留冲突，
  不使用修改时间决定哪边覆盖哪边。
- 普通 WebDAV 协议 v1 要求服务端正确支持强 ETag、`If-Match` 和 `If-None-Match`。
- 坚果云桌面通道使用协议 v2 的独立历史版本，不依赖上述条件创建行为；并发分叉保留双方。
- 同步期间的新本地修改通过版本比较保护，不被旧请求的响应覆盖。
- 远端删除使用带版本的墓碑记录；物理文件消失或服务端丢失数据不作为已确认删除传播。
- 网络错误、HTTP 错误、异常 JSON/XML、路径越界及超大响应都不会应用到本地；v1 拒绝弱 ETag，v2 校验文件内容哈希和祖先图。
- 上传后重新读取确认，处理响应丢失以及读写期间另一台设备再次修改的情况。
- IndexedDB 事务性同步状态、共同快照、持久化冲突副本；替换本地内容前保留版本历史。
- 中英文同步设置：保存目录、会话凭据、发现远端导图、逐张选择和手动同步。
- 正在编辑的导图及未提交恢复草稿暂缓同步，避免覆写编辑器；切换目录清空凭据。
- 远端删除移入回收站；冲突双方可下载为 JSON 核对包，不自动合并。

## 试用步骤与限制

请使用 Windows v0.7.0 或更新版本；v0.6.1 安装包不包含此功能。两台实际设备验证尚未完成，
请先用人工测试导图，不用唯一副本；这是实验功能，不承诺所有 WebDAV 提供商可用。

1. 在自己已有的服务中创建专用目录。坚果云请使用新版 Windows 桌面版；其他服务需支持
   HTTPS、PROPFIND、强 ETag、条件 PUT 和浏览器跨域访问。
2. 打开“设置 → 多设备同步”，保存完整目录地址（不含用户名、密码、查询参数）。
3. 输入服务的访问凭据，勾选要上传的导图后手动同步。
4. 另一设备使用相同目录，查找远端导图、勾选后同步。只保存地址不会发出请求。
5. 关闭设置会清空密码；下次需重新输入。建议用权限仅限该目录的专用凭据。

### 坚果云 Windows 桌面版

使用 Windows v0.7.0 或更新版本，新建人工导图并使用专用同步目录。v0.6.1 安装包没有此次适配。
网页版及旧桌面版会明确提示无法直接连接坚果云，不会尝试发送凭据。
坚果云地址可能包含“我的坚果云”这一层，请使用实际 WebDAV 目录，而不是电脑磁盘路径。

`src/sync/historyWebdav.ts` 将每次变化写成新的 `<map-id>--<SHA256>.ithread-sync.json` 文件。
内容包含随机标识、父版本和完整快照；哈希与文件名不符、父版本缺失或已知祖先消失时停止应用。
相同基准上同时创建或修改会形成多个末端版本，双方均保留，不采用最后写入者覆盖。
新协议暂不自动迁移旧 `<map-id>.json` 文件；发现同 ID 旧文件会停下并提示更换测试目录。

Windows 通道只允许 `dav.jianguoyun.com` 的 HTTPS 专用目录，以及 GET、PUT、Depth=1 的 PROPFIND。
主进程验证调用窗口、主框架和应用文档，拒绝任意网址、路径跳转、外部框架、任意请求头及重定向。
凭据只驻留内存；操作结束、关闭设置、窗口销毁或过期时清除，未完成请求会取消。
此通道不关闭浏览器安全设置，不是通用 HTTP 代理。

实验上限为每图 256 个远端版本、累计 128 MiB；整个目录最多发现 4096 个文件。
历史不会自动清理，每次修改会增加用户网盘占用。达到上限时保留全部历史并停止同步。
冲突仍需下载双方 JSON 核对，尚无一键合并。各端必须使用同一协议；Mac/安卓/iPad 客户端尚未实现。

坚果云以外的服务使用浏览器通道，包括桌面版中的该通道，可能受 CORS 约束。服务器需允许对应来源、
PROPFIND/GET/PUT、Authorization/Depth/If-Match/If-None-Match 请求头并暴露 ETag。
不支持这些条件时会报错，不能关闭浏览器安全设置来绕过。未配置服务不会产生云费用；
自己的服务可能有存储或流量费用。官网托管和同步存储是两件事，GitHub Pages 不存储私人导图。

## 存储协议 v1

用户选择一个已存在的专用 WebDAV 目录。同一个目录对应一个私人同步文件库，各设备使用
相同目录。每张导图存储为 `<map-id>.json`，包含 `protocolVersion`、`mapId`、`deleted`
和完整的原生导图 `document`。被删除的记录保留 `document: null`，不物理删除文件。

本阶段使用整张导图快照，保留原生内容和内嵌图片；尚不是主题级增量同步。后续附件独立存储、
内容去重和新协议版本不能通过静默改变 v1 的含义来实现。`.ithread` 文件导出格式不变。
尚无端到端加密；HTTPS 保护传输，用户选择的服务仍可读取上传内容。

## 本地适配器必须遵守的约定

1. 用户主动选择参与同步的导图；不能在启用时默认上传整个现有文件库。
2. 持久化当前内容、单调递增的本地版本及共同基准快照；普通编辑、CLI 编辑和恢复草稿
   应经过同一条版本更新路径。
3. `apply` 必须在事务中比较预期本地版本。版本已变化时返回 false，保持新内容等待重试。
4. `preserveConflict` 先持久化远端副本，同时保留当前本地内容；按导图 ID 与远端 ETag
   去重。不能把内存中的测试实现直接用作生产存储。
5. 墓碑只移入可恢复状态，不永久删除文件或历史。首次启用、切换同步目录及冲突恢复
   需要明确的用户选择和备份。
6. 本地保存成功与同步成功分别显示。离线、同步失败和凭据失效不阻断编辑。

## 测试

2026-10-15 真实坚果云人工测试通过：创建与发现、离线修改往返、上传响应丢失后重试、
分歧保留、删除标记和同时首次创建。使用两个独立模拟客户端，经过生产连接工厂和原生网络模块；
不等于两台物理设备实测。Electron 隔离窗口另行验证了真实预加载桥接、主框架鉴权及禁用 Node 访问。
没有上传用户真实导图，也没有删除测试目录中的文件。

`test/cloud-sync.test.ts` 使用内存中的设备存储和模拟 WebDAV 服务器，不访问真实云盘。
覆盖双设备传递、离线重试、并发修改、上传响应丢失、删除冲突、协议异常和路径安全。
`test/sync-local-store.test.ts` 使用模拟 IndexedDB 验证持久化、普通保存、恢复草稿、
编辑器保护、冲突去重与替换前备份，不连接真实服务。
